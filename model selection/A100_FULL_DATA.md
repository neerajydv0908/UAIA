The separate 400-pair monitor never changes model weights. The 1,452 aggregate ties are excluded from this hard-label experiment. Full data means all eligible clear training pairs, not the monitor or other held-out data.
2. **Verify the GPU and saved-state restart.** A short full-model probe measures memory/speed and checks that a saved adapter and optimizer can restart exactly. The supervisor rejects a probe with different source/data fingerprints.
3. **Load Qwen3-4B-Instruct-2507.** Original model weights stay frozen. LoRA learns small additions on all 36 layers; this is judge fine-tuning, not foundation-model pretraining or a product feature.
4. **Train once across all 4,646 pairs.** Both answer orders give 9,292 presentations. Four pairs contribute to each update; the last update uses two. Total: **1,162 updates, one epoch** (one complete pass). Small batches are still necessary for GPU memory, but they form one continuous run with one optimizer and learning schedule.
5. **Save and monitor automatically.** Every 100 updates and at the end, save model additions, Adam history and random state. Read the same 400 monitor pairs in both orders. There are 12 monitor readings and 12 saved training checkpoints, potentially several GB on Drive. Patience is disabled so monitoring cannot stop this intended full pass early; failures and time limits still stop it.
6. **Select after the full pass.** Choose the lowest monitor log-loss, with an earlier update breaking exact ties. Log-loss measures the penalty for incorrect confidence; lower is better. Keep the final update-1,162 checkpoint too. If an earlier checkpoint wins, report how many pairs it actually saw; do not describe that earlier version as trained on all 4,646.
